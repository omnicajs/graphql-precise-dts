# Документация для разработки

[English](../en/README.md) | [Все языки](../README.md)

Этот каталог помогает разработчику понять устройство генератора, проследить
выполнение операции и написать тест на его публичное поведение. Пользовательский
API и настройка пакета описаны в [основном README](../../README.md) и
[руководстве пользователя](../../docs/README.md).

## Разработка

Реализация находится в `src/`, сценарии публичного API и интеграционные проверки —
в `tests/`. Декларации генерируются во временных рабочих каталогах и сравниваются
с сохранёнными ожиданиями из `tests/fixtures/cases/`. Отдельные TypeScript-проверки
в `tests/cases/` проверяют контракты деклараций: вывод типов Apollo Client,
допустимые и недопустимые примеры использования, типы схемы и модули enum’ов.

```bash
yarn lint:fix
yarn test
yarn test:coverage
```

`yarn test` запускает проверки публичных типов, runtime-сценарии и проверки
собранного пакета. Файлы `.test-d.ts` из `tests/cases/` проверяют сохранённые
ожидания без запуска генератора. Сценарии публичного API должны побайтово
воспроизвести те же файлы. Дерево деклараций и aggregate проверяются в отдельных
TypeScript-проектах.

| Команда | Что проверяет |
|---|---|
| `yarn test` | Типы, поведение во время исполнения и собранный пакет |
| `yarn test:types` | Публичные типы API и контракты сохранённых деклараций |
| `yarn test:types:api` | Типы публичной конфигурации и Codegen |
| `yarn test:types:cases` | Сохранённые декларации фикстур в изолированных проектах `.test-d.ts` |
| `yarn test:runtime` | Сценарии публичного API, сравнение фикстур и интеграции |
| `yarn test:cases` | Сравнение выходных файлов фикстур и статические контракты деклараций |
| `yarn test:package` | Сборку, экспорты пакета, CLI, workers и потребителей Codegen |
| `yarn test:coverage` | Runtime-тесты с заданными порогами покрытия |

Помощники фикстур находятся в `tests/fixtures/`: `workspace.ts` создаёт временные
копии входов, а `generation.ts` вызывает публичный API для одного проекта
фикстуры. Сохранённые ожидания остаются неизменными при запуске любой тестовой
команды. Границы покрытия и ограничения измерений описаны в
[руководстве по тестированию](TESTING.md).

## Как пользоваться документацией

Публичные точки входа задаются `package.json#exports`, `package.json#bin` и
[конфигурацией сборки](../../vite.config.ts). Реализация этих точек входа находится
в `src/`. Документы описывают публичные контракты, внутренние модели и
последовательность работы генератора.

При изменении ответственности модуля обновляй `ARCHITECTURE.md`, при изменении
последовательности или результата выполнения — `FLOW.md`. Правила выбора
сценариев, проверок и оценки покрытия находятся в `TESTING.md`.

Внутренние функции и структуры приведены для навигации по коду. Они не становятся
публичным контрактом и не должны использоваться как точки входа тестов.
`docs-dev/` не входит в npm-пакет: список `package.json#files` включает
`dist`, пользовательский каталог `docs/`, `README.md` и `CHANGELOG.md`.

Русская и английская версии имеют одинаковый набор страниц. При изменении
контракта или устройства проекта обновляй обе версии, включая примеры и схемы.
